# OS更新の共有

iOS と Android の公式更新を、Google スプレッドシートと Apps Script で1か所に集めます。サーバも有料の API も使いません。直すかどうかは担当アプリごとにシートで判断し、**要確認** または **修正が必要** のときだけ Slack に出します。

Slack に載せるのは次の3点です。

- 何が変わったか
- 公式情報へのリンク
- 要確認観点（権限、WebView、通知、セキュリティなど）

## 料金

追加料金は発生しません。使うものは次のとおりです。

- すでに持っている Google アカウントのスプレッドシートと Apps Script
- Slack の Incoming Webhook（無料のワークスペースで作成できます）

取得は1日1回、公式ページを数件から十数件読むだけです。Apps Script の無料枠（トリガー実行 90分/日、URL取得 2万回/日）に対して、実際の使用は数秒と十数回です。

要約のための外部 AI は呼んでいません。公式ページの文章を短くしてシートに置きます。

## 保守が残るところ

普段開くのはスプレッドシートだけです。

| やりたいこと | 触る場所 |
| --- | --- |
| 担当アプリを足す、外す | アプリ シート |
| 観点のキーワードを足す | 観点キーワード シート |
| 通知する判断を変える | 設定 シートの「通知する判断」 |
| 情報源の URL を差し替える | 情報源 シート |

コードを開くのは、実行ログに同じ取得失敗が続いたときだけです。公式サイトの形が変わっても、本文が取れない更新はタイトルとリンクだけ残り、処理自体は止まりません。

判断列は自動では埋めません。キーワードが拾えない変更を、影響なしとして流さないためです。

## 毎朝の動き

1. Apple のリリース一覧と、Android のセキュリティ公開情報を読む
2. まだ見ていないものだけを **更新** に足す
3. 有効なアプリごとに **判断** へ1行足す。推定は、アプリの「見る観点」とキーワードが重なったときだけ「要確認」
4. 新しい更新があれば、未判断である旨を Slack に1通出す
5. **判断** が「要確認」または「修正が必要」で、まだ送っていない行を Slack に出す

ベータは記録だけして、Slack にも判断行にも出しません。出す場合は **設定** の「ベータも判断する」をオンにします。

初回の取得は、公開日から45日以内のものだけを判断対象にします。それより古いリリースでシートを埋めないためです。日数は **設定** の「初回に取り込む日数」で変えられます。2回目以降は、新しく出たものだけが対象です。

## セットアップ

1. [Google スプレッドシート](https://sheets.google.com) で空のシートを作る
2. メニューの **拡張機能 → Apps Script** を開く
3. 左のファイル一覧から、最初からある `Code.gs` を削除する
4. **＋ → スクリプト** でファイルを2つ作り、名前を `Logic` と `Main` にする
5. このリポジトリの `apps-script/Logic.gs` と `apps-script/Main.gs` の中身を、それぞれに貼る
6. 左の **プロジェクトの設定** で、タイムゾーンを **東京** にする
7. 上部の関数選択で `setup` を選び、**実行** する。出た権限の確認では、このスプレッドシートの編集、外部 URL への接続、トリガーの設定を許可する
8. スプレッドシートに戻る。シートが並んでいれば準備完了
9. **アプリ** シートの例を、担当アプリの名前に変える。**有効** を **オン** にする。見る観点はカンマか読点で区切る
10. Slack で Incoming Webhook を作り、URL を **設定** シートの Slack Webhook URL に貼る
    - [Slack API](https://api.slack.com/apps) でアプリを作成し、Incoming Webhooks をオンにして、知らせたいチャンネルへ追加する
    - URL は `https://hooks.slack.com/` で始まるものを使う
11. スプレッドシートを再読み込みし、メニュー **OS更新 → 毎朝8時に動かす** を実行する
12. **OS更新 → いま取得する** を実行する。初回は公式のリリースノートを読むため、1分ほどかかることがあります

Webhook が空でも取得と記録は動きます。Slack には送りません。

メンションを付けるときは、**アプリ** シートに `<!channel>` か `<@U12345678>` と書きます。`@channel` と書いた場合も、送信時に `<!channel>` へ変換します。

## 判断の入れ方

**判断** シートを開きます。列の意味は次のとおりです。

| 列 | 意味 |
| --- | --- |
| 推定 | キーワードと、そのアプリが見る観点が重なったかの目安 |
| 判断 | 未判断 / 影響なし / 要確認 / 修正が必要。ここを人が入れる |
| 要約 | Slack の「何が変わったか」。日本語に書き換えてから送ってよい |
| 観点 | Slack の「要確認観点」 |
| 理由 | 書いてあれば Slack にも添える |

判断を入れたあと、次の朝8時台に送信します。すぐ送るときは **OS更新 → 判断済みをSlackへ送る** を実行します。同じ判断は再送しません。「要確認」から「修正が必要」に変えたときは、もう一度送ります。

アプリをあとから足した場合も、**いま取得する** を実行すると、状態が「新規」の更新に判断行が足されます。

## 情報源

初期状態で入っている公式ページは次の2つです。

- Apple のリリース: <https://developer.apple.com/news/releases/rss/releases.rss>
  - **タイトルに含む** は `iOS,iPadOS`。iPhone と iPad のリリースだけを対象にし、Xcode や macOS は入れません
  - リリースノートの本文は、Apple が公開している Markdown を読みます
- Android のセキュリティ公開情報: <https://source.android.com/docs/security/bulletin/asb-overview>
  - 月次の公開情報だけを見ます。開発者ブログの記事は混ぜません

行を足せば、**種類** が `rss` の別フィードも読めます。`android-bulletin` は上記の公開情報ページ専用です。

## 動作確認

判断ロジックのテストは、このリポジトリで次を実行します。Apps Script 本体は Google 上で動きます。

```sh
node test/logic.test.js
```

`package.json` がある場合は `npm test` でも同じです。
